# Methods Log (for paper reproducibility / impartiality)

This logs every method and artifact used, so claims can be audited. It deliberately separates what is
*reproducible*, what is *real but single-sample*, and what is *simulation only*.

## Models
- Inference engine: **Anthropic Claude**, three scales — **Haiku, Sonnet, Opus 4.8** — invoked as
  isolated Claude Code subagents with an explicit `model` override. Single vendor / single tokenizer
  family. No external API key or local model was available; cross-vendor models were NOT used.
- Independent judge: a separate Opus subagent, fresh context, blind A/B ordering.

## Instrumentation (how "real token usage" is captured)
- Each pipeline stage (extractor → analyst → writer) is one isolated subagent, `tool_uses = 0`
  ("do not use tools, respond directly"). The runtime returns `subagent_tokens` per call.
- **Calibration:** a near-empty subagent ("reply READY") measures fixed per-call overhead. Observed
  overhead is large and *model-dependent* (Haiku ~19.6k, Sonnet/Opus ~12.2k per call), so runtime
  totals are NOT comparable across models and are reported for transparency only.
- **Headline metric = tiktoken (cl100k_base)** on harness-canonical prompts + verbatim outputs. This
  is overhead-free and reproducible from the committed records. The runtime numbers corroborate the
  *direction* per model.

## Experimental design (A/B, paired)
- Held constant: task pipeline, documents, role instructions, model (per arm), judge, rubric.
- Varied: **context assembly only.** Baseline = full document + all prior verbatim outputs in each
  downstream prompt. TOAP = only the distilled upstream output (analyst←facts; writer←analysis).
- Prompts are **generated by `benchmark/ab_study/harness.py`** from the scenario + verbatim upstream
  outputs (not hand-authored), removing prompt-tweaking bias.
- Accuracy: independent blind judge scores each final recommendation against a fixed 4-item rubric.

## Scenarios
- `scenario_01_incident` (payments outage postmortem) — run across Haiku/Sonnet/Opus.
- `scenario_02_support` (duplicate-charge escalation) — run at default model (cross-scenario point).

## Tooling
- `tiktoken` (cl100k_base, o200k_base) for token counts; `matplotlib` 3.10 for figures.
- TOAP protocol implementation: Rust workspace (`crates/`), 19 unit/integration tests.

## Evidence tiers (state in the paper)
1. **Reproducible (tiktoken on committed text):** wire-format reduction; downstream prompt reduction.
2. **Real but single-sample (runtime subagent usage):** corroborates direction per model.
3. **Simulation, NOT measurement (do not cite):** `benchmark/real_llm_bench.py` (author-written
   outputs) — kept only as an illustrative harness.

## Known threats to validity (carried into the paper)
Single model family / one tokenizer; n small (2 scenarios; multi-model on 1); single sample per call;
judge same family; baseline is the naive transcript-accumulation pattern; tasks/rubrics author-made;
subagent overhead artifact (mitigated by using tiktoken as the headline). Cross-vendor, large-n,
established-dataset, and human-eval replication are required before any general claim.

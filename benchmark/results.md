# TOAP Benchmark Results

> Generated by `benchmark/runner.py`. Tokens measured with tiktoken (cl100k_base, o200k_base). **Tokens, not bytes, are the real cost.** TOAP is content-lossless, so task accuracy equals the baseline by construction.

## Headline

### multi_turn_shared_doc — 8 questions about ONE shared document; baseline re-sends the doc each turn.

| Metric | WITHOUT TOAP (JSON) | WITH TOAP | Reduction |
|---|---|---|---|
| Messages | 16 | 27 | — |
| Wire bytes | 12,588 | 3,137 | **4.01×** |
| Tokens (cl100k) | 2,807 | 843 | **3.33×** |
| Tokens (o200k) | 2,831 | 841 | **3.37×** |

- Accuracy: baseline **100%**, TOAP **100%** (identical — same content delivered).

### fanout_5_workers — 1 orchestrator dispatches the same doc to 5 workers.

| Metric | WITHOUT TOAP (JSON) | WITH TOAP | Reduction |
|---|---|---|---|
| Messages | 10 | 16 | — |
| Wire bytes | 7,885 | 1,690 | **4.67×** |
| Tokens (cl100k) | 1,760 | 459 | **3.83×** |
| Tokens (o200k) | 1,775 | 458 | **3.88×** |
| Tokens cl100k (worst case: remote re-fetch) | 1,760 | 1,684 | 1.05× |

- Accuracy: baseline **100%**, TOAP **100%**.
- **Honesty note:** the strong column assumes the context store is co-located with workers (the realistic shared-broker case), so reads are local. If every worker must fetch the doc over the wire, TOAP's advantage on raw transmission shrinks toward zero (see the worst-case row) — its win then comes from prefix-caching the shared prefix, not from the wire. TOAP's clearest win is **repeated reference** (Scenario 1).

## Micro-benchmark: opcode terseness vs natural language (a MODEST win)

| TOAP payload | tokens (cl100k) | NL equivalent | tokens (cl100k) | token saving |
|---|---|---|---|---|
| `SUM(CTX:42)?max_words=150` | 10 | Please summarize document 42 in at most 150 words. | 12 | 17% |
| `CLS(CTX:55)?labels=spam,ham` | 11 | Classify document 55 as either spam or ham. | 11 | 0% |
| `ANS(CTX:1)?q=revenue_change` | 10 | Using document 1, what was the revenue change? | 11 | 9% |

This confirms the research: symbolic opcodes save only ~10–20% of *tokens* vs natural language (punctuation fragments under BPE). The big savings come from context-by-ID deduplication (above), not from terse opcodes.

## What this proves / does not prove

- **Proves:** when the same context is referenced repeatedly, TOAP cuts inter-agent tokens and bytes dramatically with **zero accuracy loss** (content is delivered intact).
- **Does not prove:** any reduction in the *worker's own LLM prompt tokens* — once an agent puts the fetched document into a model prompt, that cost is unchanged. TOAP saves *coordination/transport*, not inference, unless paired with prefix caching or summarization.
- **Does not claim** the opcode layer is a big win; it is measured at ~10–20%.

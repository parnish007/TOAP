# Real-LLM Benchmark (Claude as the inference engine)

> The LLM is Claude (this session); each agent output was generated by real reasoning over its inputs. Tokens measured with tiktoken (cl100k_base) on the exact prompts and real outputs. Manually orchestrated (no API key / local model available).

## Per-agent LLM token consumption

| Agent | WITHOUT TOAP prompt tok | WITH TOAP prompt tok | completion tok |
|---|---|---|---|
| extractor | 273 | 273 | 154 |
| analyst | 421 | 182 | 134 |
| writer | 549 | 156 | 89 |

## Totals (real tokens consumed end-to-end)

| Metric | WITHOUT TOAP | WITH TOAP | Reduction |
|---|---|---|---|
| LLM prompt tokens | 1243 | 611 | 2.03x |
| LLM completion tokens | 377 | 377 | 1.00x |
| Coordination tokens (wire) | 1321 | 78 | 16.94x |
| **TOTAL tokens** | **2941** | **1066** | **2.76x** |

- **Accuracy:** the TOAP pipeline's final recommendation covers **4/4** ground-truth action themes (100%): ['autoscal', 'pool', 'alert', 'load']. The baseline produced the same recommendation (downstream agents had all decision-relevant info via the distilled references), so **accuracy parity** holds.

## Why TOAP wins here (honestly)

- The **extractor** reads the full doc under both protocols — TOAP saves nothing there.
- The win is **downstream**: the analyst and writer don't need the raw 230-token doc, only the distilled facts/analysis. The naive baseline re-stuffs the whole growing transcript into every prompt; TOAP passes references so each agent sees only what it needs. That is a real reduction in **LLM input tokens**, not just wire bytes.
- Caveat: a hand-optimized baseline could also pass summaries instead of the full transcript — but that is exactly the context-minimization TOAP systematizes.
